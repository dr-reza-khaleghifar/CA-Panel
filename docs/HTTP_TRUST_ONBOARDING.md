# Iran CA Center — راهنمای HTTP اعتماد به Root CA

## هدف و محدودیت امنیتی

مسیر \`http://ca1.iravand.ir/\` یک راهنمای استاتیک فارسی برای نصب و بررسی اعتماد به Root CA است. این صفحه از HTTP قابل دسترسی است تا کاربران بتوانند فایل عمومی Root CA و راهنمای نصب آن را دریافت کنند. خود پرتال عمومی روی HTTPS با گواهی ACME عمومی ارائه می‌شود؛ نصب Root خصوصی برای ورود به سایت لازم نیست.

**HTTP امن یا احرازاصالت‌شده نیست.** مهاجم دارای امکان دست‌کاری ترافیک می‌تواند HTML، فایل دانلودی یا اثر انگشت نمایش‌داده‌شده در صفحه را تغییر دهد. بنابراین اثر انگشت SHA-256 را حتماً از یک کانال مستقل و از قبل مورداعتماد از مدیر CA دریافت و با اثر انگشت فایل دانلودشده تطبیق دهید. محتوای همین صفحه HTTP مرجع مستقل اعتماد نیست.

اگر کاربر برای دریافت راهنمای Root به صفحه HTTP نیاز دارد، باید آدرس آن را دستی وارد کند. HTTPS-Only یا HSTS ممکن است HTTP را مسدود کند. درخواست گواهی و پیگیری عمومی فقط روی HTTPS انجام می‌شود.

## مسیرهای مجاز روی پورت ۸۰

Caddy فقط درخواست‌های \`GET\` و \`HEAD\` را برای این مسیرها سرو می‌کند:

| مسیر | کاربرد |
| --- | --- |
| \`/\` | صفحه راهنمای HTML |
| \`/trust.js\` | اسکریپت محلی جست‌وجو، آکاردئون و کپی |
| \`/downloads/ca-panel-root-ca.pem\` | گواهی عمومی Root CA با قالب PEM |
| \`/downloads/ca-panel-root-ca.cer\` | همان گواهی عمومی Root CA با قالب DER |

تمام مسیرهای دیگر پاسخ \`404\` می‌دهند؛ از جمله \`/login\`، \`/api/*\`، \`/static/*\`، \`/root-ca.pem\`، \`/.env\` و مسیرهای دانلود ناشناخته. هیچ reverse proxy از HTTP به API وجود ندارد.

فقط فایل‌های استاتیک راهنما، اسکریپت رابط و دو نسخه **گواهی عمومی Root CA** در ریشه onboarding مونت می‌شوند. کلید خصوصی Root، کلید Issuer، رمزها، فایل \`.env\`، داده‌های پایگاه‌داده، فرم ورود، MFA و بسته خصوصی ZIP هرگز از این مسیر سرو نمی‌شوند. پاسخ‌ها دارای CSP محدود، \`X-Frame-Options: DENY\`، \`X-Content-Type-Options: nosniff\` و \`Cache-Control: no-store\` هستند.

## نصب روی Ubuntu موجود

\`\`\`bash
cd ~/CA-Panel
git pull --ff-only
bash install.sh --public-https
\`\`\`

این دستور تنظیمات موجود \`.env\` و فایل‌های CA را حفظ می‌کند، سرویس API و Caddy پروفایل \`private-tls\` را با Compose بازسازی/اجرا می‌کند و سلامت HTTPS را بررسی می‌کند. دیتابیس یا کلیدهای موجود را حذف نکنید و برای به‌روزرسانی صفحه، CA جدید نسازید. اگر مواد Root آفلاین هنوز داخل \`secrets/offline/\` روی سرور آنلاین باشد، نصاب عمداً متوقف می‌شود؛ آن مواد را به محل آفلاین امن منتقل کنید. اگر پورت ۸۰ توسط سرویس دیگری اشغال شده است، ابتدا تداخل را رفع کنید. در صورت نیاز، \`PANEL_HTTP_BIND_IP\` را در \`.env\` برای محدودکردن IP شنونده HTTP تنظیم کنید.

## بررسی پس از نصب

روی خود سرور، پاسخ مسیرهای مجاز و غیرمجاز را بررسی کنید:

\`\`\`bash
curl --noproxy '*' -H 'Host: ca1.iravand.ir' -I http://127.0.0.1/
curl --noproxy '*' -H 'Host: ca1.iravand.ir' -I http://127.0.0.1/trust.js
curl --noproxy '*' -H 'Host: ca1.iravand.ir' -I http://127.0.0.1/downloads/ca-panel-root-ca.pem
curl --noproxy '*' -H 'Host: ca1.iravand.ir' -I http://127.0.0.1/downloads/ca-panel-root-ca.cer
curl --noproxy '*' -H 'Host: ca1.iravand.ir' -I http://127.0.0.1/login
curl --noproxy '*' -H 'Host: ca1.iravand.ir' -I http://127.0.0.1/api/requests
\`\`\`

انتظار پاسخ به‌ترتیب: **200، 200، 200، 200، 404، 404**.

سلامت HTTPS را بدون خاموش‌کردن اعتبارسنجی TLS بررسی کنید:

\`\`\`bash
curl --noproxy '*' --resolve ca1.iravand.ir:443:127.0.0.1 \\
  https://ca1.iravand.ir/healthz
\`\`\`

نتیجه مورد انتظار: \`{"status":"ok"}\`. گواهی HTTPS خود پرتال از ACME عمومی است و نباید برای بررسی آن Root خصوصی را به curl بدهید. Root CA خصوصی فقط برای اعتماد به گواهی‌های صادرشده برای دامنه کاربران استفاده می‌شود؛ آن را از کانال مستقل دریافت و SHA-256 را تطبیق دهید.

## تست خودکار

\`tests/test_http_trust_onboarding.py\` پیکربندی Caddy، mountهای فقط‌خواندنی و متادیتای صفحه را کنترل می‌کند. \`tests/check_http_trust.sh\` Caddy واقعی را با گواهی آزمایشی اجرا و مسیرهای مجاز و غیرمجاز HTTP را بررسی می‌کند. \`tests/trust_probe_behavior_check.js\` رفتار جست‌وجو، آکاردئون و کپی را بررسی می‌کند. این تست‌ها از کلید یا داده CA تولیدی استفاده نمی‌کنند.
