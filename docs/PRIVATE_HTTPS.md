# راه‌اندازی CA-Panel با گواهی اختصاصی CA روی HTTPS و پورت ۴۴۳

این روش برای `https://ca1.iravand.ir` (یا هر دامنه‌ای که در `PANEL_DOMAIN` قرار داده‌اید) از **گواهی سرور صادرشده با Issuing CA خودتان** استفاده می‌کند. سرور HTTPS با Caddy اجرا می‌شود و برنامه FastAPI در شبکه خصوصی Docker در پورت ۸۰۰۰ باقی می‌ماند. مسیر مدیریتی `127.0.0.1:8080` در میزبان همچنان فعال است؛ در شبکه عمومی منتشر نمی‌شود.

## ۱. تنظیم دامنه در .env
بدون حذف رمز Issuing CA یا بازنویسی تنظیمات دیگر، این مقادیر را در `.env` تنظیم کنید:

```dotenv
PANEL_DOMAIN=ca1.iravand.ir
PANEL_TLS_HOST_DIR=./secrets/tls
```

DNS دامنه باید به IP سرور یا مسیر شبکه قابل دسترس کاربران اشاره کند. اگر فقط شبکه داخلی استفاده می‌کنید، DNS داخلی مناسب است.

## ۲. گرفتن گواهی TLS از CA خودتان

اگر گواهی و کلید TLS مخصوص همین دامنه را **قبلاً** دارید، به مرحله ۳ بروید. در غیر این صورت:

1. پنل فعلی را از مسیر محلی `http://127.0.0.1:8080` باز کنید.
2. `ca1.iravand.ir` را در فرم درخواست ثبت کنید.
3. رکورد DNS TXT اعلام‌شده در پنل را منتشر کرده و مالکیت دامنه را تأیید کنید.
4. گزینه صدور گواهی را بزنید و ZIP حاوی کلید خصوصی را **همان بار اول** دانلود کنید.

داخل ZIP به‌صورت پیش‌فرض این فایل‌ها وجود دارند:
`ca1.iravand.ir.crt`، `ca1.iravand.ir.key`،
`ca1.iravand.ir-fullchain.pem`، `issuing-ca.pem` و `root-ca.pem`.

**هرگز** فایل `secrets/online/issuer-key.pem` یا Root خصوصی را جای فایل کلید TLS سایت قرار ندهید. گواهی TLS سایت باید یک **leaf/serverAuth** با SAN مطابق `ca1.iravand.ir` باشد.

## ۳. نصب امن ZIP بدون غیرفعال‌کردن بررسی گواهی

از ریشه مخزن، **روی همان سروری که Docker اجرا می‌شود**، این دستور را اجرا کنید:

```bash
python3 scripts/setup_private_tls.py --zip "$HOME/Downloads/ca1.iravand.ir-certificates.zip"
```

اسکریپت بدون دسترسی شبکه، با OpenSSL سیستم بررسی می‌کند:
- نام DNS در SAN گواهی موجود باشد.
- زنجیره گواهی Issuing CA به Root CA واقعی داخل `CA_ONLINE_HOST_DIR` معتبر باشد.
- کلید خصوصی مخصوص دامنه با کلید عمومی گواهی مطابقت داشته و گواهی منقضی نشده باشد.
- فایل `fullchain.pem` دقیقاً شامل گواهی سرور و Issuing CA باشد.

سپس فقط `fullchain.pem` و `privkey.pem` را در `PANEL_TLS_HOST_DIR` قرار می‌دهد. محل نصب، از Git و Docker build مستقل و پوشه `secrets/` در `.gitignore` مستثنا است. کلید سایت با مجوز ۰۶۰۰ ذخیره می‌شود.

اگر نسخه قبلی گواهی TLS نصب شده و در حال تمدید هستید، پس از اطمینان از فایل جدید، از `--replace` استفاده کنید. این گزینه **هیچ گواهی Root/Issuing CA را عوض نمی‌کند**.

## ۴. اجرای Caddy با گواهی خودتان روی ۴۴۳

اگر قبلاً حالت `public`/ACME را فعال کرده‌اید، ابتدا آن را متوقف کنید تا دو سرویس روی پورت ۴۴۳ تداخل نداشته باشند:

```bash
docker compose --profile public stop caddy
```

سپس یکی از این دو روش کافی است:

```bash
bash install.sh --private-https
# یا:
# docker compose --profile private-tls up -d --build api caddy-private
```

در این حالت، Caddy فایل‌ها را به‌صورت **فقط‌خواندنی** از `PANEL_TLS_HOST_DIR` بارگذاری می‌کند و HTTPS روی TCP/UDP 443 برقرار می‌شود. **پورت ۸۰ در حالت خصوصی منتشر نمی‌شود.** اجرای همزمان پروفایل‌های `public` و `private-tls` روی یک میزبان باعث خطای اشغال پورت ۴۴۳ می‌شود.

## ۵. بررسی واقعی اعتبار گواهی و سلامت HTTPS

در همان میزبان، از گواهی Root عمومی خودتان برای بررسی زنجیره و نام دامنه استفاده کنید:

```bash
docker compose --profile private-tls ps
curl --noproxy '*' --cacert secrets/online/root-cert.pem \
  --resolve ca1.iravand.ir:443:127.0.0.1 \
  https://ca1.iravand.ir/healthz
```

خروجی موفق `{"status":"ok"}` است. اگر مسیر گواهی Root شما سفارشی است، در `--cacert` همان فایل عمومی را مشخص کنید. در مرورگر Firefox سفارشی نیز `https://ca1.iravand.ir` را باز و صادرکننده گواهی را بررسی کنید.

**نکته اعتماد:** مرورگر سفارشی شما تنها اگر Root CA را واقعاً در مخزن اعتماد خود داشته باشد به این گواهی اعتماد می‌کند؛ مرورگرهای عمومی بدون نصب و اعتماد به Root شما ممکن است هشدار گواهی نشان دهند. این گواهی به‌صورت خودکار در مخازن اعتماد عمومی جهانی معتبر نمی‌شود.

## ۶. تمدید گواهی

Caddy در این حالت **گواهی شما را به‌صورت خودکار تمدید نمی‌کند**. پیش از انقضای leaf (پیش‌فرض ۳۰ روز)، گواهی تازه‌ای برای همان دامنه با TXT جدید صادر و ZIP آن را با ابزار بالا نصب کنید:

```bash
python3 scripts/setup_private_tls.py --zip "/path/to/new-ca1.iravand.ir-certificates.zip" --replace
docker compose --profile private-tls restart caddy-private
```

فایل ZIP حاوی کلید خصوصی بدون رمز است؛ پس از نصب، آن را در محل امن نگه دارید یا به روش مناسب از روی میزبان حذف کنید. **رمز CA، کلید Root، کلید Issuing CA یا ZIP خصوصی را در GitHub آپلود نکنید.** اگر پورت ۴۴۳ توسط سرویس دیگری اشغال است، آن سرویس را شناسایی کرده و تنظیمات را با احتیاط اصلاح کنید.
