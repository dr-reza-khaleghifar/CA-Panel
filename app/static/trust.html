راهنمای رسمی نصب گواهی ریشه

برای اتصال امن، گواهی ریشه را بررسی و فقط در صورت اعتماد نصب کنید.

این صفحه راهنمای دریافت و نصب گواهی عمومی Root CA سامانه CA-Panel است. روش نصب بسته به سیستم‌عامل، نسخه دستگاه، مرورگر و سیاست‌های سازمانی متفاوت است.

هشدار امنیتی مهم — این یک Root CA خصوصی و آزمایشی است. نصب آن به دستگاه شما اجازه می‌دهد گواهی‌هایی را که این CA صادر می‌کند معتبر بداند. این اعتماد فقط به سایت CA-Panel محدود نیست. فقط در دستگاهی که مالک یا مدیر مجاز آن هستید و پس از تأیید مستقل اثر انگشت نصب کنید. این Root CA در فهرست عمومی اعتماد مرورگرها قرار ندارد و جایگزین یک CA عمومی مورد اعتماد اینترنت نیست.

اگر فقط می‌خواهید سایت را ببینید، لازم نیست این گواهی را نصب کنید. هشدار مرورگر را نادیده نگیرید و اطلاعات ورود را در صفحه‌ای که هشدار گواهی دارد وارد نکنید.

۱. دریافت گواهی عمومی Root CA

هر دو فایل زیر فقط شامل گواهی عمومی هستند؛ هیچ کلید خصوصی یا رمز عبوری در آن‌ها وجود ندارد.

برای Linux، ChromeOS و بسیاری از ابزارها PEM مناسب است. برای Windows، Android و دستگاه‌های Apple معمولاً فایل CER/DER انتخاب ساده‌تری است؛ پشتیبانی دقیق به نسخه دستگاه بستگی دارد.

۲. قبل از نصب، اثر انگشت را مستقل بررسی کنید

دانلود از همین وب‌سایت به‌تنهایی اصالت فایل را ثابت نمی‌کند؛ مخصوصاً اگر صفحه با HTTP باز شده باشد. اثر انگشت زیر را از مدیر CA از یک کانال مستقل و از قبل مورد اعتماد دریافت کنید و با خروجی دستگاه خودتان مقایسه کنید.

C3:A4:F7:93:EB:50:68:4E:3E:98:EB:42:A2:EB:C9:E3:09:DA:56:81:51:1D:EA:AC:E2:B9:C4:72:CF:AE:30:D5
مقایسه باید دقیق باشد. تمام ۳۲ بایت اثر انگشت SHA-256 باید یکسان باشند. اگر حتی یک رقم متفاوت است، فایل را نصب نکنید و آن را به مدیر سامانه گزارش دهید.

Windows — PowerShell یا CMD

برای فایل CER با کدگذاری DER:

certutil -hashfile ca-panel-root-ca.cer SHA256

macOS / Linux — OpenSSL

برای فایل CER با کدگذاری DER:

openssl x509 -inform DER -in ca-panel-root-ca.cer -noout -fingerprint -sha256

برای فایل PEM:

openssl x509 -in ca-panel-root-ca.pem -noout -fingerprint -sha256

۳. راهنمای نصب بر اساس سیستم‌عامل و دستگاه

پس از تأیید اثر انگشت، فقط راهنمای مربوط به دستگاه خود را دنبال کنید. نام منوها ممکن است با نسخه سیستم‌عامل یا سازنده دستگاه کمی تفاوت داشته باشد.

Windows 11 و Windows 10
  1. فایل ca-panel-root-ca.cer را دانلود و اثر انگشت آن را با دستور بخش قبل بررسی کنید.
  2. برای اعتماد فقط در حساب کاربری فعلی، PowerShell را باز کنید و اجرا کنید:
certutil -user -addstore Root "$env:USERPROFILE\Downloads\ca-panel-root-ca.cer"

اگر فایل در پوشه Downloads نیست، مسیر را با محل واقعی فایل جایگزین کنید.

برای تمام کاربران همین رایانه: فقط اگر مدیر دستگاه هستید، Terminal یا PowerShell را با گزینه Run as administrator باز کنید و اجرا کنید:

certutil -addstore -f Root "$env:USERPROFILE\Downloads\ca-panel-root-ca.cer"

روش گرافیکی:

  1. Win + R را بزنید و mmc را اجرا کنید.
  2. از File گزینه Add/Remove Snap-in را باز کنید.
  3. Certificates را Add کنید و برای نصب سراسری Computer account و سپس Local computer را انتخاب کنید.
  4. به Trusted Root Certification Authorities → Certificates بروید.
  5. روی Certificates راست‌کلیک کنید، All Tasks → Import را انتخاب کنید و فایل CER تأییدشده را وارد کنید.

برای فقط حساب فعلی می‌توانید از certmgr.msc استفاده کنید؛ برای مخزن کل رایانه از certlm.msc.

مرورگرها: Chrome و Edge معمولاً از سازوکار اعتماد سیستم استفاده می‌کنند. Firefox ممکن است به واردکردن جداگانه در بخش Authorities نیاز داشته باشد.

راهنمای رسمی Microsoft درباره مخزن Trusted Root

macOS — MacBook و iMac
  1. فایل CER یا PEM را دانلود و اثر انگشت را با OpenSSL بررسی کنید.
  2. برنامه Keychain Access را از Spotlight باز کنید.
  3. برای اعتماد سراسری، زنجیره System را انتخاب کنید؛ برای اعتماد محدود به حساب فعلی، login را انتخاب کنید.
  4. از منوی File گزینه Import Items را بزنید و فایل گواهی را وارد کنید. ممکن است رمز مدیر دستگاه درخواست شود.
  5. گواهی واردشده را باز کنید، بخش Trust را گسترش دهید و فقط پس از بررسی اثر انگشت، سیاست When using this certificate را روی Always Trust قرار دهید.

روش خط فرمان برای مدیر دستگاه:

sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ~/Downloads/ca-panel-root-ca.cer

پس از نصب، مرورگر را ببندید و دوباره باز کنید. Safari از مخزن اعتماد سیستم استفاده می‌کند؛ Firefox ممکن است تنظیم جداگانه بخواهد.

راهنمای Apple برای افزودن گواهی به Keychain

iPhone و iPad — iOS / iPadOS
  1. با Safari فایل ca-panel-root-ca.cer را دانلود کنید.
  2. Settings را باز کنید. اگر گزینه Profile Downloaded نمایش داده شد، آن را انتخاب کنید؛ در غیر این صورت به General → VPN & Device Management بروید و پروفایل دانلودشده را پیدا کنید.
  3. جزئیات گواهی را بررسی کنید و فقط در صورت تطبیق اثر انگشت، Install را بزنید.
  4. سپس به Settings → General → About → Certificate Trust Settings بروید.
  5. در بخش Enable Full Trust for Root Certificates، اعتماد کامل به این Root CA را فعال و پیام تأیید را قبول کنید.
مهم در دستگاه‌های Appleنصب پروفایل به‌تنهایی لزوماً اعتماد SSL را فعال نمی‌کند؛ مرحله Certificate Trust Settings جداگانه لازم است. در دستگاه‌های سازمانی، نصب از طریق MDM یا Apple Configurator را به مدیر فناوری اطلاعات بسپارید.

راهنمای رسمی Apple برای فعال‌کردن Full Trust در iOS و iPadOS

Android — Pixel، Samsung، Xiaomi و سایر گوشی‌ها
  1. فایل ca-panel-root-ca.cer را دانلود کنید.
  2. Settings → Security & privacy → More security settings → Encryption & credentials را باز کنید. نام منو در گوشی‌های مختلف متفاوت است.
  3. Install a certificate را انتخاب کنید و گزینه CA certificate را بزنید؛ فایل را از Downloads انتخاب کنید.
  4. در صورت درخواست، PIN، الگو یا رمز قفل دستگاه را وارد کنید و نامی مانند CA-Panel Test Root را ثبت کنید.
  5. در بخش Trusted credentials → User می‌توانید وجود گواهی نصب‌شده را بررسی کنید.
محدودیت مهم Androidدر Android 7 و نسخه‌های جدیدتر، برنامه‌هایی که برای API 24 به بالا هدف‌گذاری شده‌اند به‌طور پیش‌فرض فقط به CAهای سیستمی اعتماد می‌کنند؛ بنابراین نصب User CA تضمین نمی‌کند همه اپلیکیشن‌ها آن را بپذیرند. توسعه‌دهنده هر اپ باید در صورت نیاز trust anchor مناسب را در تنظیمات امنیت شبکه برنامه تعریف کند. برنامه‌های دارای certificate pinning نیز ممکن است آن را نپذیرند.

Linux — Ubuntu و Debian

فایل PEM را دانلود کنید و در پوشه Downloads قرار دهید. سپس اجرا کنید:

sudo install -m 0644 ~/Downloads/ca-panel-root-ca.pem /usr/local/share/ca-certificates/ca-panel-root-ca.crt
sudo update-ca-certificates

برای بررسی گواهی نصب‌شده:

ls -l /etc/ssl/certs | grep ca-panel-root-ca

این روش مخزن اعتماد سیستم را به‌روزرسانی می‌کند. بعضی برنامه‌های Snap یا برنامه‌هایی با مخزن گواهی اختصاصی ممکن است به تنظیم جداگانه نیاز داشته باشند.

مستندات رسمی Ubuntu برای نصب Root CA

Linux — Fedora، RHEL، Rocky و AlmaLinux

گواهی PEM را به پوشه trust anchors اضافه و مخزن اعتماد را به‌روزرسانی کنید:

sudo install -m 0644 ~/Downloads/ca-panel-root-ca.pem /etc/pki/ca-trust/source/anchors/ca-panel-root-ca.pem
sudo update-ca-trust extract

اگر دستور update-ca-trust موجود نیست، بسته مدیریت گواهی توزیع خود را نصب کنید.

Linux — Arch و توزیع‌های مبتنی بر Arch 
sudo install -m 0644 ~/Downloads/ca-panel-root-ca.pem /etc/ca-certificates/trust-source/anchors/ca-panel-root-ca.pem
sudo trust extract-compat

در صورت نبود ابزار trust، بسته p11-kit را از مخزن رسمی توزیع نصب کنید.

ChromeOS و Chromebook
  1. فایل PEM را دانلود کنید؛ در روش مدیریت سازمانی Google، فایل باید PEM باشد و DER پذیرفته نمی‌شود.
  2. در نوار آدرس Chrome عبارت chrome://certificate-manager را وارد کنید.
  3. بخش Authorities را باز کنید و Import را بزنید.
  4. گواهی را انتخاب و فقط گزینه‌های اعتماد مورد نیاز برای شناسایی وب‌سایت‌ها را فعال کنید.

در Chromebookهای تحت مدیریت مدرسه یا سازمان، نصب را از مدیر Google Admin بخواهید؛ مدیر می‌تواند CA را از Devices → Networks → Certificates توزیع کند.

راهنمای Google برای تنظیم و توزیع CA در ChromeOS

مرورگرها — Firefox، Chrome، Edge و Safari

Firefox در Windows، macOS و Linux

  1. Settings → Privacy & Security → Certificates → View Certificates را باز کنید.
  2. در زبانه Authorities گزینه Import را بزنید.
  3. فایل PEM یا CER تأییدشده را انتخاب کنید.
  4. گزینه Trust this CA to identify websites را فقط پس از تأیید اثر انگشت فعال کنید.

در بعضی نسخه‌ها می‌توانید استفاده از گواهی‌های اعتمادشده سیستم را فعال کنید؛ رفتار Firefox به نسخه و سیاست‌های سازمانی بستگی دارد.

Chrome و Edge

در Windows و macOS معمولاً از مخزن اعتماد سیستم‌عامل استفاده می‌کنند. در Linux و ChromeOS، روش نصب به توزیع و سیاست مرورگر بستگی دارد. اگر پس از نصب هنوز خطای ناشناخته‌بودن صادرکننده می‌بینید، مخزن گواهی خود مرورگر را بررسی کنید.

Safari

Safari در دستگاه‌های Apple از زنجیره اعتماد سیستم استفاده می‌کند. نصب و فعال‌سازی اعتماد را از طریق Keychain در macOS یا Certificate Trust Settings در iOS/iPadOS انجام دهید.

راهنمای Mozilla برای مدیریت CAها در Firefox

Java و برنامه‌های دارای مخزن گواهی اختصاصی

برخی برنامه‌ها از مخزن اعتماد سیستم‌عامل استفاده نمی‌کنند. برای یک truststore اختصاصی Java می‌توانید اجرا کنید:

keytool -importcert -alias ca-panel-root -file ca-panel-root-ca.cer -keystore ca-panel-truststore.p12 -storetype PKCS12

رمز را در پاسخ به prompt وارد کنید و اثر انگشت نمایش‌داده‌شده را با مقدار تأییدشده مقایسه کنید. سپس برنامه را با truststore ساخته‌شده پیکربندی کنید. از تغییر سراسری فایل cacerts جاوا بدون هماهنگی مدیر سیستم خودداری کنید.

تلویزیون هوشمند، کنسول بازی، روتر و دستگاه‌های IoT

برای این دستگاه‌ها روش عمومی و یکسانی وجود ندارد. بسیاری از آن‌ها نصب Root CA سفارشی را پشتیبانی نمی‌کنند یا فقط گواهی‌های از پیش نصب‌شده را می‌پذیرند. فقط مستندات سازنده همان مدل و نسخه را دنبال کنید؛ هرگز فایل یا گواهی را با روش‌های غیررسمی روی دستگاه نصب نکنید.

۴. پس از نصب، اتصال را آزمایش کنید

مرورگر را کاملاً ببندید و دوباره باز کنید. سپس نشانی HTTPS پنل را وارد کنید. نباید هشدار ناشناخته‌بودن صادرکننده یا نام دامنه مشاهده شود.

هشدار را دور نزنید. از گزینه‌هایی مانند Proceed anyway، Continue to site یا غیرفعال‌کردن بررسی TLS برای استفاده روزمره استفاده نکنید. اگر خطا باقی ماند، ابتدا تاریخ و ساعت دستگاه، نام دامنه، نصب Root CA و زنجیره گواهی را بررسی کنید.
رفتن به پنل امن CA-Panel

۵. چگونه اعتماد را حذف کنیم؟

  • Windows: در certmgr.msc یا certlm.msc به Trusted Root Certification Authorities → Certificates بروید و فقط گواهی CA-Panel را که اثر انگشت آن با مقدار همین صفحه تطبیق دارد حذف کنید.
  • macOS: Keychain Access را باز کنید، گواهی CA-Panel را در keychain مربوطه پیدا و حذف کنید.
  • iPhone / iPad: پروفایل مربوط به CA-Panel را از VPN & Device Management حذف کنید و در صورت نیاز Full Trust را خاموش کنید.
  • Android: در Encryption & credentials بخش User credentials گواهی CA-Panel را انتخاب و حذف کنید.
  • Ubuntu / Debian: فایل را از /usr/local/share/ca-certificates حذف و سپس sudo update-ca-certificates --fresh اجرا کنید.
  • Fedora / RHEL: فایل را از /etc/pki/ca-trust/source/anchors حذف و sudo update-ca-trust extract اجرا کنید.
  • Arch: فایل را از trust-source/anchors حذف و sudo trust extract-compat اجرا کنید.

سؤالات متداول

آیا نصب این گواهی باعث می‌شود همه وب‌سایت‌های اینترنت معتبر شوند؟

خیر. این گواهی فقط زنجیره‌هایی را معتبر می‌کند که به همین Root CA ختم شوند. وب‌سایت‌هایی که از CAهای عمومی دیگر گواهی دارند از این نصب سودی نمی‌برند.

آیا این CA به‌صورت پیش‌فرض در Chrome، Firefox یا Safari معتبر است؟

خیر. این CA خصوصی و آزمایشی است و عضو مخازن عمومی اعتماد مرورگرها نیست. برای اعتماد باید آن را به‌صورت آگاهانه در دستگاه یا مرورگر نصب کنید.

چرا بعد از نصب، بعضی برنامه‌های Android هنوز خطا می‌دهند؟

برنامه‌های جدید Android به‌طور پیش‌فرض ممکن است به گواهی‌های نصب‌شده توسط کاربر اعتماد نکنند. توسعه‌دهنده برنامه باید trust anchor را صریحاً پیکربندی کند؛ certificate pinning نیز می‌تواند مانع اتصال شود.

آیا می‌توانم این گواهی را روی دستگاه شرکت یا شخص دیگری نصب کنم؟

فقط با مجوز صریح مالک یا مدیر مجاز دستگاه و پس از تأیید اثر انگشت از کانال مستقل. نصب Root CA روی دستگاه دیگران بدون رضایت و اطلاع کامل آن‌ها مناسب نیست.

این صفحه راهنمای نصب یک Root CA خصوصی و آزمایشی است؛ نصب آن اختیاری است و به معنی تأیید عمومی CA-Panel یا عضویت در برنامه‌های اعتماد عمومی مرورگرها نیست.
