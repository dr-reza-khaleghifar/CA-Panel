مرکز رسمی راهنمای نصب گواهی ریشه

برای اعتماد به گواهی‌های صادرشده توسط CA-Panel، Root CA را فقط در صورت نیاز نصب کنید.

برای ورود به پرتال عمومی ca1.iravand.ir نیازی به نصب Root خصوصی نیست؛ HTTPS خود سایت با گواهی عمومی تأمین می‌شود. اگر می‌خواهید به گواهی‌های دامنه‌ای صادرشده توسط Private CA اعتماد کنید، Root CA را پس از بررسی اثر انگشت مستقل روی دستگاه مقصد نصب کنید.

مرحله ۱: دریافت گواهی عمومی ریشه (Root CA)

گواهی عمومی ریشه CA-Panel را با فرمت مناسب دریافت کنید و سپس طبق مراحل زیر روی دستگاه خود نصب کنید.

این فایل‌ها فقط گواهی عمومی هستند؛ کلید خصوصی در آن‌ها وجود ندارد.

PEM

گواهی با فرمت PEM (.pem)

مناسب Linux، macOS، OpenSSL و ابزارهای خط فرمان

/downloads/ca-panel-root-ca.pem
DER

گواهی با فرمت DER (.cer)

مناسب Windows، دستگاه‌های Apple و بسیاری از ابزارها

/downloads/ca-panel-root-ca.cer
توجه مهم: اعتماد به یک Root CA به معنی اعطای اختیار اعتماد گسترده است.

با نصب این گواهی، دستگاه شما می‌تواند گواهی‌هایی را که CA-Panel صادر می‌کند معتبر بداند. این اعتماد فقط به سایت CA-Panel محدود نیست. آن را فقط روی دستگاهی نصب کنید که مالک یا مدیر مجاز آن هستید و پس از تطبیق اثر انگشت از یک کانال مستقل.

مرحله ۲: بررسی اثر انگشت قبل از نصب

برای اطمینان از اصالت فایل، اثر انگشت SHA-256 را روی دستگاه خود محاسبه و با مقدار تأییدشده زیر مقایسه کنید.

اثر انگشت گواهی ریشه (SHA-256) مقدار رسمی CA-Panel
0E:3B:D2:5A:45:8A:0A:7E:48:5F:0C:2F:F1:BD:8A:67:59:6A:B2:47:D7:74:D2:64:31:D8:3C:44:1A:12:A6:06
مقایسه باید مستقل و دقیق باشد.

چون دریافت اولیه فایل از طریق HTTP ممکن است انجام شود، فقط به عددی که در همین صفحه می‌بینید اکتفا نکنید. اثر انگشت را از یک کانال مستقل و مورد اعتماد نیز دریافت کنید. اگر حتی یک رقم متفاوت است، گواهی را نصب نکنید.

Windows — PowerShell / CMD

برای فایل CER با کدگذاری DER:

certutil -hashfile ca-panel-root-ca.cer SHA256
macOS / Linux — OpenSSL

برای فایل CER:

openssl x509 -inform DER -in ca-panel-root-ca.cer -noout -fingerprint -sha256

برای فایل PEM:

openssl x509 -in ca-panel-root-ca.pem -noout -fingerprint -sha256

مرحله ۳: انتخاب راهنمای نصب بر اساس سیستم‌عامل یا دستگاه

دستگاه خود را انتخاب کنید. دستورالعمل‌ها در بخش‌های بازشونده قرار دارند تا سریع‌تر به راهنمای موردنظر برسید.

Windows 10 / 11Windows Certificate Store
  1. فایل ca-panel-root-ca.cer را دانلود و اثر انگشت آن را بررسی کنید.
  2. برای اعتماد فقط در حساب کاربری فعلی، PowerShell را باز و اجرا کنید:
certutil -user -addstore Root "$env:USERPROFILE\Downloads\ca-panel-root-ca.cer"

اگر فایل در پوشه Downloads نیست، مسیر را با محل واقعی فایل جایگزین کنید.

برای تمام کاربران همین رایانه: فقط اگر مدیر دستگاه هستید، Terminal یا PowerShell را با گزینه Run as administrator باز کنید و اجرا کنید:

certutil -addstore -f Root "$env:USERPROFILE\Downloads\ca-panel-root-ca.cer"

روش گرافیکی:

  1. Win + R را بزنید و mmc را اجرا کنید.
  2. از File گزینه Add/Remove Snap-in را باز کنید.
  3. Certificates را Add کنید و برای نصب سراسری Computer account و سپس Local computer را انتخاب کنید.
  4. به Trusted Root Certification Authorities → Certificates بروید.
  5. روی Certificates راست‌کلیک کنید، All Tasks → Import را انتخاب و فایل CER تأییدشده را وارد کنید.

برای حساب فعلی می‌توانید از certmgr.msc و برای مخزن کل رایانه از certlm.msc استفاده کنید.

مرورگرها: Chrome و Edge معمولاً از سازوکار اعتماد سیستم استفاده می‌کنند. Firefox ممکن است به واردکردن جداگانه در بخش Authorities نیاز داشته باشد.

راهنمای رسمی Microsoft درباره Trusted Root
macOS — MacBook و iMacKeychain Access
  1. فایل CER یا PEM را دانلود و اثر انگشت را با OpenSSL بررسی کنید.
  2. برنامه Keychain Access را از Spotlight باز کنید.
  3. برای اعتماد سراسری، زنجیره System و برای اعتماد محدود به حساب فعلی، login را انتخاب کنید.
  4. از منوی File گزینه Import Items را بزنید و فایل گواهی را وارد کنید. ممکن است رمز مدیر دستگاه درخواست شود.
  5. گواهی واردشده را باز کنید، بخش Trust را گسترش دهید و فقط پس از بررسی اثر انگشت، سیاست When using this certificate را روی Always Trust قرار دهید.

روش خط فرمان برای مدیر دستگاه:

sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ~/Downloads/ca-panel-root-ca.cer

پس از نصب، مرورگر را ببندید و دوباره باز کنید. Safari از مخزن اعتماد سیستم استفاده می‌کند؛ Firefox ممکن است تنظیم جداگانه بخواهد.

راهنمای Apple برای افزودن گواهی به Keychain
iPhone / iPad — iOS / iPadOSProfile و Certificate Trust Settings
  1. با Safari فایل ca-panel-root-ca.cer را دانلود کنید.
  2. Settings را باز کنید. اگر گزینه Profile Downloaded نمایش داده شد، آن را انتخاب کنید؛ در غیر این صورت به General → VPN & Device Management بروید و پروفایل دانلودشده را پیدا کنید.
  3. جزئیات گواهی را بررسی کنید و فقط در صورت تطبیق اثر انگشت، Install را بزنید.
  4. به Settings → General → About → Certificate Trust Settings بروید.
  5. در بخش Enable Full Trust for Root Certificates، اعتماد کامل به این Root CA را فعال و پیام تأیید را قبول کنید.
مهم در دستگاه‌های Apple

نصب پروفایل به‌تنهایی لزوماً اعتماد SSL را فعال نمی‌کند؛ مرحله Certificate Trust Settings جداگانه لازم است. در دستگاه‌های سازمانی، نصب از طریق MDM یا Apple Configurator را به مدیر فناوری اطلاعات بسپارید.

راهنمای رسمی Apple برای فعال‌کردن Full Trust در iOS و iPadOS
Android — Pixel، Samsung، XiaomiInstall a CA certificate
  1. فایل ca-panel-root-ca.cer را دانلود کنید.
  2. Settings → Security & privacy → More security settings → Encryption & credentials را باز کنید. نام منو در گوشی‌های مختلف متفاوت است.
  3. Install a certificate را انتخاب و گزینه CA certificate را بزنید؛ فایل را از Downloads انتخاب کنید.
  4. در صورت درخواست، PIN، الگو یا رمز قفل دستگاه را وارد کنید و نامی مانند CA-Panel Root CA ثبت کنید.
  5. در بخش Trusted credentials → User می‌توانید وجود گواهی نصب‌شده را بررسی کنید.
محدودیت مهم Android

در Android 7 و نسخه‌های جدیدتر، برنامه‌هایی که برای API 24 به بالا هدف‌گذاری شده‌اند به‌طور پیش‌فرض فقط به CAهای سیستمی اعتماد می‌کنند؛ بنابراین نصب User CA تضمین نمی‌کند همه اپلیکیشن‌ها آن را بپذیرند. توسعه‌دهنده هر برنامه باید در صورت نیاز trust anchor را در تنظیمات امنیت شبکه تعریف کند. برنامه‌های دارای certificate pinning نیز ممکن است آن را نپذیرند.

Ubuntu / DebianSystem CA trust store

فایل PEM را دانلود کنید و در پوشه Downloads قرار دهید. سپس اجرا کنید:

sudo install -m 0644 ~/Downloads/ca-panel-root-ca.pem /usr/local/share/ca-certificates/ca-panel-root-ca.crt
sudo update-ca-certificates

برای بررسی گواهی نصب‌شده:

ls -l /etc/ssl/certs | grep ca-panel-root-ca

این روش مخزن اعتماد سیستم را به‌روزرسانی می‌کند. بعضی برنامه‌های Snap یا برنامه‌هایی با مخزن گواهی اختصاصی ممکن است به تنظیم جداگانه نیاز داشته باشند.

مستندات رسمی Ubuntu برای نصب Root CA
Fedora / RHEL / Rocky / AlmaLinuxShared system trust

گواهی PEM را به پوشه trust anchors اضافه و مخزن اعتماد را به‌روزرسانی کنید:

sudo install -m 0644 ~/Downloads/ca-panel-root-ca.pem /etc/pki/ca-trust/source/anchors/ca-panel-root-ca.pem
sudo update-ca-trust extract

اگر دستور update-ca-trust موجود نیست، بسته مدیریت گواهی توزیع خود را از مخزن رسمی نصب کنید.

Arch Linux و توزیع‌های مبتنی بر Archp11-kit trust anchors 
sudo install -m 0644 ~/Downloads/ca-panel-root-ca.pem /etc/ca-certificates/trust-source/anchors/ca-panel-root-ca.pem
sudo trust extract-compat

در صورت نبود ابزار trust، بسته p11-kit را از مخزن رسمی توزیع نصب کنید.

ChromeOS / ChromebookChrome certificate manager
  1. فایل PEM را دانلود کنید؛ در روش مدیریت سازمانی Google، فایل باید PEM باشد و DER پذیرفته نمی‌شود.
  2. در نوار آدرس Chrome عبارت chrome://certificate-manager را وارد کنید.
  3. بخش Authorities را باز کنید و Import را بزنید.
  4. گواهی را انتخاب و فقط گزینه‌های اعتماد مورد نیاز برای شناسایی وب‌سایت‌ها را فعال کنید.

در Chromebookهای تحت مدیریت مدرسه یا سازمان، نصب را از مدیر Google Admin بخواهید؛ مدیر می‌تواند CA را از Devices → Networks → Certificates توزیع کند.

Firefox در Windows، macOS و Linux

  1. Settings → Privacy & Security → Certificates → View Certificates را باز کنید.
  2. در زبانه Authorities گزینه Import را بزنید.
  3. فایل PEM یا CER تأییدشده را انتخاب کنید.
  4. گزینه Trust this CA to identify websites را فقط پس از تأیید اثر انگشت فعال کنید.

در بعضی نسخه‌ها می‌توانید استفاده از گواهی‌های اعتمادشده سیستم را فعال کنید؛ رفتار Firefox به نسخه و سیاست‌های سازمانی بستگی دارد.

Chrome و Edge

در Windows و macOS معمولاً از مخزن اعتماد سیستم‌عامل استفاده می‌کنند. در Linux و ChromeOS، روش نصب به توزیع و سیاست مرورگر بستگی دارد. اگر پس از نصب هنوز خطای ناشناخته‌بودن صادرکننده می‌بینید، مخزن گواهی خود مرورگر را بررسی کنید.

Safari

Safari در دستگاه‌های Apple از زنجیره اعتماد سیستم استفاده می‌کند. نصب و فعال‌سازی اعتماد را از طریق Keychain در macOS یا Certificate Trust Settings در iOS/iPadOS انجام دهید.

راهنمای Mozilla برای مدیریت CAها در Firefox
Java و مخازن گواهی اختصاصیJava KeyStore / PKCS12

برخی برنامه‌ها از مخزن اعتماد سیستم‌عامل استفاده نمی‌کنند. برای یک truststore اختصاصی Java می‌توانید اجرا کنید:

keytool -importcert -alias ca-panel-root -file ca-panel-root-ca.cer -keystore ca-panel-truststore.p12 -storetype PKCS12

رمز را در پاسخ به prompt وارد کنید و اثر انگشت نمایش‌داده‌شده را با مقدار تأییدشده مقایسه کنید. سپس برنامه را با truststore ساخته‌شده پیکربندی کنید. از تغییر سراسری فایل cacerts جاوا بدون هماهنگی مدیر سیستم خودداری کنید.

تلویزیون هوشمند، کنسول بازی، روتر و IoTEmbedded and managed devices

برای این دستگاه‌ها روش عمومی و یکسانی وجود ندارد. بسیاری از آن‌ها نصب Root CA سفارشی را پشتیبانی نمی‌کنند یا فقط گواهی‌های از پیش نصب‌شده را می‌پذیرند. فقط مستندات سازنده همان مدل و نسخه را دنبال کنید؛ هرگز فایل یا گواهی را با روش‌های غیررسمی روی دستگاه نصب نکنید.

راهنمایی با این عبارت پیدا نشد. نام سیستم‌عامل را کوتاه‌تر وارد کنید.

مرحله ۴: نصب و آزمایش اتصال

پس از نصب و اعتماد به Root، مرورگر را دوباره باز کنید و یک وب‌سایت یا سرویس داخلی را که گواهی آن توسط CA-Panel صادر شده است آزمایش کنید. پرتال عمومی CA-Panel از HTTPS عمومی استفاده می‌کند و برای ورود به آن به نصب Root خصوصی نیاز ندارید.

حذف اعتماد در صورت عدم نیاز اختیاری

اگر دیگر به CA-Panel نیاز ندارید، می‌توانید گواهی ریشه را از فهرست گواهی‌های مورد اعتماد دستگاه خود حذف کنید. پس از حذف، گواهی‌های صادرشده توسط این CA دیگر از طریق این Root CA معتبر شناخته نمی‌شوند.

  • Windows: در certmgr.msc یا certlm.msc به Trusted Root Certification Authorities → Certificates بروید و فقط گواهی CA-Panel را که اثر انگشت آن با مقدار رسمی تطبیق دارد حذف کنید.
  • macOS: در Keychain Access گواهی CA-Panel را در keychain مربوطه پیدا و حذف کنید.
  • iPhone / iPad: پروفایل CA-Panel را از VPN & Device Management حذف کنید و در صورت نیاز Full Trust را خاموش کنید.
  • Android: در Encryption & credentials بخش User credentials گواهی CA-Panel را انتخاب و حذف کنید.
  • Ubuntu / Debian: فایل را از /usr/local/share/ca-certificates حذف و سپس sudo update-ca-certificates --fresh اجرا کنید.
  • Fedora / RHEL: فایل را از /etc/pki/ca-trust/source/anchors حذف و sudo update-ca-trust extract اجرا کنید.
  • Arch: فایل را از trust-source/anchors حذف و sudo trust extract-compat اجرا کنید.

سؤالات متداول

پاسخ پرسش‌های رایج درباره نصب، اعتماد و استفاده از گواهی ریشه CA-Panel

آیا این گواهی در همه مرورگرها به‌صورت پیش‌فرض معتبر است؟

خیر. CA-Panel یک CA خصوصی است و در مخازن عمومی اعتماد مرورگرها قرار ندارد. برای اعتماد باید آن را آگاهانه در مخزن سیستم‌عامل یا مرورگر نصب کنید.

بعد از نصب، چگونه متوجه شوم که گواهی به‌درستی اعتماد شده است؟

مرورگر را کاملاً ببندید و دوباره باز کنید، سپس وب‌سایتی را که گواهی آن توسط CA-Panel صادر شده با HTTPS باز کنید. پرتال عمومی خود CA-Panel به Root خصوصی نیاز ندارد. اگر سرویس داخلی هنوز خطا می‌دهد، مخزن اعتماد، تاریخ و ساعت دستگاه و نام دامنه را بررسی کنید.

آیا نصب این گواهی روی دستگاه شخصی ریسک امنیتی دارد؟

بله، نصب Root CA به صادرکننده آن اختیار اعتماد گسترده می‌دهد. فقط در صورتی نصب کنید که به اپراتور CA و دستگاه اعتماد دارید، مالک یا مدیر مجاز دستگاه هستید و اثر انگشت را از یک کانال مستقل بررسی کرده‌اید.

فرق بین فرمت‌های PEM و CER چیست و کدام را دانلود کنم؟

PEM نمایش متنی Base64 از گواهی است و معمولاً برای Linux، macOS و OpenSSL مناسب است. فایل CER این سامانه با قالب باینری DER ساخته شده و برای Windows و بسیاری از ابزارهای گرافیکی مناسب‌تر است. هر دو به یک گواهی ریشه اشاره می‌کنند.

چرا بعضی برنامه‌های Android بعد از نصب هنوز خطا می‌دهند؟

برخی برنامه‌های جدید Android به‌صورت پیش‌فرض به CAهای نصب‌شده توسط کاربر اعتماد نمی‌کنند یا از certificate pinning استفاده می‌کنند. نصب گواهی در سیستم تضمین نمی‌کند همه برنامه‌ها آن را بپذیرند.

اگر دیگر به CA-Panel نیاز نداشته باشم، چگونه اعتماد را حذف کنم؟

از راهنمای مرحله پنجم برای سیستم‌عامل خود استفاده کنید و فقط گواهی‌ای را حذف کنید که نام و اثر انگشت آن با CA-Panel مطابقت دارد. گواهی‌های ریشه دیگر را حذف نکنید.
